## Что нужно для изолированной проверки

Сборка на Vercel читает объекты из API по адресу `API_BASE_URL` (по умолчанию боевой
`https://immo-tonn.de/api`). Для теста нужен **отдельный API с отдельной базой, доступный из
интернета** — сборочные машины Vercel не видят ваш компьютер.

### Тестовый backend — два варианта

**A. Временный, на вашем Mac (все средства уже есть).** Установлены `mongod` (v6.0),
`cloudflared` (2026.8.3), Vercel CLI с вашим входом. Тот же набор, что использует
`e2e/rebuild-e2e.mjs`, но вместо mock-Vercel — настоящий Vercel:

1. Временная база: `mongod --dbpath <tmp> --port 27199 --bind_ip 127.0.0.1`.
2. Настоящий backend из ветки (`cd BE && npx tsc && node dist/app.js`) с окружением (ничего
   боевого не наследовать — запускать с чистым `env -i`): `MONGO_URI=mongodb://127.0.0.1:27199/immo_e2e`,
   `JWT_SECRET=<случайная тестовая строка>`, `PORT=39001`, `FRONTEND_DEPLOY_HOOK_URL=<тестовый хук>`,
   `REBUILD_DEBOUNCE_MS=5000`.
3. Тестовый админ: одна запись в `immo_e2e` скриптом (как в `e2e/rebuild-e2e.mjs`), JWT подписать
   тестовым секретом.
4. Публичный адрес: `cloudflared tunnel --url http://127.0.0.1:39001` → `https://<случайное>.trycloudflare.com`.
   Адрес меняется при каждом запуске туннеля; открыт весь тестовый API (только тестовые данные).
5. Компьютер не должен засыпать, пока идёт проверка (≈ 20–30 мин).

**B. Постоянный, на сервере Hetzner.** Отдельный docker-compose-проект (свой контейнер Mongo с
собственным томом, свой backend на другом порту, отдельный поддомен с TLS). Нужен ваш доступ к
серверу и DNS/nginx для поддомена — этого я без вас сделать не могу, DNS и серверные настройки не
менял. Подходит, если проверку надо повторять.

### Preview-ветка

Ветка **`test/vercel-e2e`** от текущего коммита прототипа: в ней же настройки Preview (переменные и
хук привязываются к ветке). Preview-деплои PR #2 при этом не меняются и по-прежнему читают боевой
API (только GET).

### Переменные (только для ветки `test/vercel-e2e`, окружение Preview)

| Где | Переменная | Значение |
|---|---|---|
| Vercel (Preview, git-branch `test/vercel-e2e`) | `API_BASE_URL` | `https://<туннель>/api` (читает `react-router.config.ts` при сборке) |
| | `VITE_API_BASE_URL` | то же (читает код в браузере: loaders и хуки) |
| | `VITE_HOST` | `https://<туннель>` — **обязательно**, иначе админка/форма в этом Preview пойдёт на боевой backend |
| Тестовый backend | `MONGO_URI`, `JWT_SECRET`, `PORT` | тестовые (см. выше) |
| | `FRONTEND_DEPLOY_HOOK_URL` | адрес хука тестовой ветки (секрет) |
| | `REBUILD_DEBOUNCE_MS` | `5000` |

Сверку (`FRONTEND_BUILD_INFO_URL`) на Preview включать нельзя: сайт закрыт авторизацией, backend не
прочитает `build-info.json`. Её проверка на реальном Vercel возможна только на открытом адресе (см.
«Что остаётся»).

Создание (после вашего разрешения; синтаксис проверен по `--help` CLI):

```
vercel env add API_BASE_URL preview --git-branch test/vercel-e2e      # то же для VITE_API_BASE_URL и VITE_HOST
vercel deploy-hooks create e2e-test --project immo --ref test/vercel-e2e
```

Хук на ветку, отличную от `dev`, запускает только Preview-деплой этой ветки.

## Проверки

Для чтения защищённого Preview — ваш авторизованный браузер (так проверялось раньше) или
`vercel curl` (побочные эффекты не выяснялись — сначала посмотреть документацию). Для каждого шага:
время «сохранено» → «хук принят» (лог backend: `ПРИНЯТ Vercel`) → «Ready» нового деплоя (`gh api
repos/Immo-Tonn/immo.com/deployments`, статус `success`) → результат. «Принят» ≠ «опубликован».

0. **Базовая сборка:** пуш ветки → Preview собирается на пустом тестовом каталоге
   (регрессия «пустой каталог»: `/immobilien/_empty` не в sitemap) → создать 1 тестовый объект.
1. **Создание** (`POST /api/objects` с тестовым JWT): до окончания сборки URL объекта → 404, в списке нет;
   после: URL → 200, H1/title/canonical, объект в списке, `sitemap.xml`, `built-objects.json`; отпечаток
   `build-info.json` = отпечаток `GET /api/objects` (формула из `FE/scripts/fingerprint.mjs`).
2. **Изменение** (`PUT`): до сборки прежний HTML; после — новый H1/title/список.
3. **Удаление** (`DELETE`): до сборки URL ещё 200; после — 404, нет в списке, sitemap, `built-objects.json`.
4. **Сбой хука:** неверный адрес в `FRONTEND_DEPLOY_HOOK_URL` → объект сохраняется (ответ 2xx), в логе
   ошибка после 3 попыток.
5. **Принято, но сборка упала:** указать в Preview-переменной недоступный `API_BASE_URL` → хук принят,
   деплой в статусе Error, предыдущий Preview не изменён; вернуть переменную → следующий запуск
   публикует.
6. **Серия правок:** 3 правки подряд → в логе один запуск, один деплой.

Шаблон проверки в консоли браузера на открытом Preview (подставить `ID` и ожидаемый H1):

```js
const ID = '<id объекта>', EXPECT = '<ожидаемый H1>';
const html = await (await fetch(`/immobilien/${ID}`, {cache: 'no-store'})).text();
const bi = await (await fetch('/build-info.json', {cache: 'no-store'})).json();
const sm = await (await fetch('/sitemap.xml', {cache: 'no-store'})).text();
({status: (await fetch(`/immobilien/${ID}`)).status,
  h1: (html.match(/<h1[^>]*>([\s\S]*?)<\/h1>/) || [])[1]?.replace(/<[^>]+>/g, '').trim() === EXPECT,
  inSitemap: sm.includes(`/immobilien/${ID}<`), fingerprint: bi.fingerprint.slice(0, 10)});
```

## Уборка после проверки

Удалить хук (`vercel deploy-hooks remove <id>`) и три переменные ветки; остановить туннель, backend и
`mongod`, удалить временную базу; удалить ветку `test/vercel-e2e`; убедиться, что Production не
менялся (последний Production-деплой `4e85507`, `gh api repos/Immo-Tonn/immo.com/deployments?environment=Production`).

## Риски и меры

- **`VITE_HOST` в Preview** указывает на боевой backend (переменная без привязки к ветке). Админка и
  форма контакта в Preview тестовой ветки без собственного `VITE_HOST` могут создать **настоящие**
  объекты/заявки. Меры: переопределить `VITE_HOST` для ветки; в проверке не открывать админку и форму
  в Preview; объекты создавать только прямыми запросами к тестовому API.
- Хук на `dev` нельзя создавать для теста — он запускает Production-деплой.
- Адрес хука и тестовый JWT — секреты: не коммитить, не публиковать.
- Туннель `trycloudflare` публичен и временен: в нём только тестовые данные; после проверки закрыть.
- Если `API_BASE_URL` Preview остался указывающим на закрытый туннель, ветка перестанет собираться —
  после проверки переменные удалить.

## Что остаётся непроверяемым на Preview

Сверка с опубликованным сайтом (`FRONTEND_BUILD_INFO_URL`): Preview закрыт авторизацией. Варианты:
включить «Protection Bypass for Automation» (изменение настройки проекта) и добавить в backend
передачу заголовка (небольшая правка кода — не сделана); либо привязать к тестовой ветке отдельный
домен на `immo-tonn.com` (изменение DNS — не делалось); либо проверить сверку на боевом домене после
слияния. До этого сверка проверена только в изолированном окружении (`e2e/rebuild-e2e.mjs`).
