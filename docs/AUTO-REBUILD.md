# Автопересборка сайта после изменения объектов

Статический сайт (prerender) показывает объекты, которые были в API **на момент сборки**.
Чтобы новые, изменённые и удалённые объекты появлялись сами, backend запускает пересборку
через Vercel Deploy Hook и дополнительно сверяет опубликованный сайт с данными.

> **Статус.** Механизм проверен полностью в **изолированном** окружении (настоящий backend,
> временная локальная MongoDB, настоящие сборки frontend, mock вместо Vercel): 24 из 24
> проверок, см. ниже. **С настоящим Vercel и боевым backend не проверен**: реальный Deploy
> Hook не создавался и не вызывался. Объявлять автообновление полностью готовым рано.

## Два состояния: «принято» и «опубликовано»

Успешный ответ Deploy Hook (200 и `job.id`) означает только, что Vercel **принял** запуск
сборки. Сборка может упасть, и тогда сайт не изменится. Поэтому:

- «принято» — ответ хука (в лог: `запуск сборки ПРИНЯТ Vercel … Это ещё не публикация`);
- «опубликовано» — на сайте `build-info.json` содержит отпечаток, совпадающий с текущими
  данными (в лог: `ОПУБЛИКОВАНО: отпечаток сайта совпал с данными`).

## Как это работает

**1. Событие (быстрый путь).** `POST/PUT/DELETE /api/objects[/:id]` →
`requestFrontendRebuild()` (`BE/src/utils/rebuildHook.ts`) **после** успешного сохранения и
ответа клиенту. Серия изменений сливается в один запуск (пауза `REBUILD_DEBOUNCE_MS`,
30 с, но не дольше `REBUILD_MAX_WAIT_MS`, 5 мин). До 3 попыток при сбое хука. Сбой хука не
влияет на сохранение объекта и на ответ API. Адрес хука — только в
`FRONTEND_DEPLOY_HOOK_URL`, в логи не попадает.

**2. Сверка (страховка, `BE/src/utils/rebuildReconciler.ts`).** Событие может потеряться:
перезапуск backend в паузе, сбой хука, падение сборки Vercel, правка уже после того, как
сборка прочитала данные. Сверка при старте backend и далее каждые 10 мин:

1. берёт текущие данные (`GET /api/objects`) и считает отпечаток (sha256 канонического JSON;
   тот же алгоритм в `FE/scripts/fingerprint.mjs`, совпадение проверено тестом);
2. читает `build-info.json` с опубликованного сайта (`FRONTEND_BUILD_INFO_URL`);
3. не совпало → сайт отстаёт → запускает хук. Совпало → ничего.

Защита от лишних запусков: пока есть отложенный запуск по событию — сверка не вмешивается;
после принятого запуска ждёт `cooldown` (10 мин, больше обычной сборки); при каждом
следующем повторе без сходимости интервал удваивается (10 → 20 → 40 мин, потолок 60); после
5 запусков подряд без результата сверка останавливается (ошибка в логе) до изменения данных
или перезапуска — чтобы не упереться в лимит Vercel (60 запусков/час). Если API или сайт
недоступны, сверка ничего не запускает (нельзя сравнить). Нет `build-info.json` (404) —
считается «не опубликовано» (первый запуск).

Включается **только** если заданы `FRONTEND_DEPLOY_HOOK_URL` и `FRONTEND_BUILD_INFO_URL`;
без них не делает ничего.

## Что видит пользователь между сохранением и готовой сборкой (минуты)

| Событие | До окончания пересборки |
|---|---|
| Новый объект | в списке нет, URL отвечает HTTP 404 (страница 404) |
| Изменённый объект | в HTML прежние данные; после загрузки тихо обновляются из API |
| Удалённый объект | URL ещё отдаёт старый HTML (200), после загрузки — «объект удалён»; из списка исчезает сразу |
| sitemap | прежний |

Если запуск или сама сборка не удались — сайт остаётся прежним до ближайшей сверки.

## Найденное при проверке

- **Пустой каталог ломал сборку.** React Router запрещает `loader` у маршрута, который ни
  разу не пререндерится; при нуле объектов маршрут объекта не пререндерился → сборка
  падала. Исправлено: при пустом каталоге пререндерится служебный путь
  `/immobilien/_empty` (под `noindex`, не в sitemap).
- **Одновременные изменения и сборка:** чтение списка и чтение карточек идут разными
  запросами; правка между ними даёт HTML новее отпечатка — сверка один раз пересоберёт
  (безвредно).

## Сквозной тест (изолированное окружение)

`e2e/rebuild-e2e.mjs` (`BE_NODE_MODULES=<путь к BE/node_modules> node e2e/rebuild-e2e.mjs`,
нужен `mongod`; ~2 минуты). Никаких боевых адресов и секретов: временная база в tmp-каталоге
на `127.0.0.1:27199`, backend на `:39001` с тестовым JWT-секретом, mock-Vercel на `:39002`,
сайт на `:39003`; переменные окружения боевого backend не наследуются; всё удаляется после
прогона. Mock-Vercel принимает хук ответом 200, **затем** собирает сайт и публикует его
только при успешной сборке; умеет падать и отменять предыдущую сборку (как Vercel).

| Сценарий | Проверено |
|---|---|
| A. Первая публикация | сайта и `build-info.json` нет → сверка сама запускает сборку |
| B. Создание | до сборки URL → 404 и нет в списке; после — 200, H1/title в HTML, список, sitemap, `built-objects.json` |
| C. Изменение | до сборки прежний HTML; после — новые H1/title/список |
| D. Создание и удаление | после удаления URL → 404, объекта нет в списке, sitemap, `built-objects.json` |
| E. Перезапуск backend в паузе | процесс убит до вызова хука (запуск потерян), после старта сверка запускает сборку, сайт обновляется |
| F1. Правка во время сборки (событие) | предыдущая сборка отменена, опубликована последняя версия |
| F2. Правка без события во время сборки | сборка публикует устаревшие данные, сверка замечает расхождение, новая сборка → актуально |
| G. Неудачная сборка Vercel | хук принят (200), сборка упала, сайт не изменён; сверка повторяет запуск → опубликовано |

Автотесты на mock-серверах: `cd BE && npm run test:rebuild` — 21 проверка (хук: успех, слияние,
повторы, лимит, недоступный сервер, секрет не в логах, контроллеры; сверка: перезапуск, принято ≠
опубликовано, изменение во время сборки, рост интервала и предел, сайт/API недоступны,
совпадение алгоритма отпечатка FE и BE).

## Что нужно сделать для подключения (я этого не делал; production и расписания не менялись)

1. Vercel: проект → Settings → Git → Deploy Hooks → создать хук на **публикуемую ветку**
   (Production Branch — `dev`, подтверждено в настройках проекта; хук на `dev` запускает Production-деплой). До слияния для проверки —
   отдельный хук на ветку `feat/seo-prerender-prototype` (только Preview). До 5 хуков на
   проект, до 60 запусков в час.
2. Адрес хука — секрет. Только в окружении backend-сервера (Hetzner, docker-compose):
   `FRONTEND_DEPLOY_HOOK_URL`; не коммитить, не вставлять в чаты и логи.
3. Для сверки: `FRONTEND_BUILD_INFO_URL` = публичный адрес `build-info.json` боевого сайта
   (после слияния это `https://immo-tonn.com/build-info.json`; для проверки на Preview —
   адрес Preview, но он защищён Vercel Authentication, и backend не сможет его прочитать).
4. Необязательно: `REBUILD_DEBOUNCE_MS`, `REBUILD_MAX_WAIT_MS`, `REBUILD_RECONCILE_INTERVAL_MS`,
   `REBUILD_RECONCILE_STARTUP_DELAY_MS`, `REBUILD_RECONCILE_COOLDOWN_MS`,
   `REBUILD_RECONCILE_MAX_ATTEMPTS`; `REBUILD_RECONCILE_API_URL` (по умолчанию backend
   обращается к самому себе: `http://127.0.0.1:$PORT/api/objects`).
5. Перезапустить контейнер `my-backend` (вручную на сервере). Выключить механизм — убрать
   переменные и перезапустить.

## Как проверить на настоящем Vercel

Конкретный план с тестовым backend, ветками и переменными — [VERCEL-E2E-PLAN.md](VERCEL-E2E-PLAN.md). Ниже — краткий перечень.

1. Создать **тестовый** объект при заданном хуке; в логе backend `ПРИНЯТ Vercel`; в Vercel — новый
   Preview-деплой; после сборки объект в списке, URL → 200, объект в `sitemap.xml` и
   `built-objects.json`; `build-info.json` обновился.
2. Удалить тестовый объект → после сборки URL → 404, из sitemap исчез.
3. Указать неверный адрес хука → сохранение объекта проходит, в логе ошибка.
4. Остановить backend на 1 минуту после правки (до истечения паузы 30 с), запустить —
   через ~1–2 мин сверка запускает сборку.
(Preview защищён Vercel Authentication — для п. 4 сверки нужен публичный `build-info.json`, то есть
проверку сверки целиком можно сделать только на Production после слияния.)

## Ограничения

- Хук вызывается только из контроллера объектов. Отдельные эндпоинты фото/видео его не
  вызывают; после загрузки фото админка делает `PUT /objects/:id` (порядок изображений),
  он и запускает сборку. Изменение самих файлов медиа без правки объекта сверка не видит
  (в отпечатке — данные объектов, включая список id изображений, но не содержимое медиа).
- Сверка работает при условии, что backend запущен; на время простоя backend обновлений нет.
- Лимит Vercel 60 запусков/час; серия правок сливается в один запуск.
- Сверка читает `/api/objects` у самого backend: если API недоступен, сверка пропускается.
