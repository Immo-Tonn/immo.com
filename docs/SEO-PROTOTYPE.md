# Прототип: prerender + языковые URL (React Router framework mode)

Ветка `feat/seo-prerender-prototype`, draft PR. Цель — проверить, что проект можно перевести
на prerender с языковыми URL без смены стека (Vite + React Router 7). Это прототип, не
готовая миграция. Откат — [ROLLBACK.md](ROLLBACK.md).

## Что сделано

- `FE/react-router.config.ts` — `ssr: false` + `prerender()`: страницы × 3 языка и все объекты
  из API (`/api/objects`). Если API недоступен — **сборка падает** (прежний деплой остаётся).
- `FE/src/routes.ts` — необязательный языковой сегмент `:lang?` (`/` = DE, `/en/…`, `/ru/…`;
  `/de/…` и прочее — 404).
- `FE/src/root.tsx`, `entry.client.tsx` — html-оболочка (бывший `index.html`: Usercentrics, GA,
  JSON-LD RealEstateAgent/WebSite, OG- и geo-теги).
- `FE/src/lang-layout.tsx` — язык задаётся URL, а не `localStorage`.
- `FE/src/routes/*` — маршруты с `meta` (title, description, canonical, hreflang, OG) для Home,
  списка объектов, карточки объекта, Wertermittlung. Данные объектов попадают в HTML через
  loader'ы (`shared/api/propertyLoaders.ts`).
- `FE/src/seo/readiness.json` — какие языки каждой страницы **готовы** (см. ниже).
- `FE/scripts/postbuild.mjs` — `404.html` (копия SPA-fallback) и `sitemap.xml`.
- `FE/vercel.json` — `outputDirectory: build/client`, rewrites только для админ-маршрутов.
- `LanguageSwitcher` — ссылки на ту же страницу с другим префиксом.

## 1. Новый объект: что происходит на самом деле

Статический вариант: **новый объект появляется в HTML, sitemap и выдаче только после успешной
пересборки** (её должен запускать Deploy Hook из backend — не реализован). До этого:

| Запрос на URL объекта, которого нет в prerender | HTTP | Содержимое |
|---|---|---|
| прямой, обычный User-Agent | 404 | оболочка `404.html` (4623 Б), без title и H1 |
| прямой, User-Agent Googlebot | 404 | **байт-в-байт тот же ответ** (одинаковый SHA) |
| переход по ссылке внутри приложения (из списка) | — (запроса документа нет) | страница открывается: `clientLoader` берёт данные из API, title и H1 объекта |
| перезагрузка этого URL в браузере | 404 | оболочка, затем приложение рисует объект (title/H1 объекта) |

Выдача **не зависит от User-Agent**: 404 получают все. Последствия, которые нужно принять:
пользователь по прямой ссылке видит страницу, но HTTP-статус 404 (превью в мессенджерах
не появится, поисковик не проиндексирует) — до завершения пересборки. Удалённый объект до
пересборки отдаёт 200 из старого HTML (его заменяет только новая сборка).

Проверено локально на эмуляции статического хостинга (удалены файлы одного объекта из сборки),
а на Vercel — только поведение для **несуществующих** ID (404, см. раздел 4): создать
реальный новый объект для проверки без изменения данных нельзя.

## 2. Конфликт peer-зависимостей

`@react-router/dev@7.7.1` объявляет необязательную peer-зависимость
`@react-router/serve@^7.7.1`. npm при разрешении берёт самую свежую версию из диапазона —
`@react-router/serve@7.18.5`, у которой peer `react-router@7.18.5` (точная версия), а в
проекте `react-router@7.7.1` (его тянет `react-router-dom@7.7.1`) → `ERESOLVE`.

Решение без `legacy-peer-deps`: добавить `@react-router/serve@7.7.1` в devDependencies
(в сборке не участвует; нужен, чтобы peer разрешился на ту же версию). Вся группа остаётся на
7.7.1, ничего не обновлялось. Проверено: `npm ci` (строгий) проходит, `npm run build`, `tsc -b`
(0 ошибок), сборка на Vercel без `FE/.npmrc` — успешна. Альтернатива (поднять всё
семейство до 7.18.5) в изолированной проверке упёрлась в тот же `ERESOLVE` при поэтапной
установке и не нужна. `FE/.npmrc` удалён.

## 3. Sitemap: 48 → 18 URL

Прежние 48 = 12 страниц × 3 языка + 4 объекта × 3 языка, независимо от готовности. Теперь
sitemap, hreflang и `noindex` строятся по одному реестру `FE/src/seo/readiness.json`
(страница → готовые языки; не указано — только `de`):

- готовы все три языка: `/wertermittlung` (есть редакторские переводы title/description и
  переведённый интерфейс) → 3 URL, hreflang `de`/`en`/`ru`/`x-default`;
- остальные 12 DE-страниц (как в прежнем sitemap) и DE-карточки объектов → без hreflang;
- EN/RU версии остальных страниц **не в sitemap, без hreflang и с `noindex`** (доступны
  пользователям): описание объектов — только по-немецки, тексты Home EN/RU временные,
  у остальных страниц нет мета.

Итого 18 = 12 + 4 + 2. Страница получает hreflang только если готовы ≥ 2 языков.

## 4. Проверка на Vercel (Preview, защита Vercel Authentication не менялась)

Проверено в вашем авторизованном браузере (только чтение), коммит `f81f021`:

| Проверка | Результат |
|---|---|
| Прямое открытие и обновление | `/`, `/en`, `/ru/immobilien`, `/immobilien`, объект DE/EN, `/wertermittlung`, `/en/wertermittlung`: 200, HTML с H1 и title; reload после перехода между языками — без ошибок |
| Настоящие 404 | `/zzz-nope`, `/de/immobilien`, `/immobilien/000…0`, `/immobilien/aaa…a` → HTTP **404** (оболочка 404.html, SPA рисует 404-экран) |
| Админ-rewrites | `/add-property`, `/edit-object/<id>` → 200 (SPA-fallback) |
| `.data` | файлы отдаются 200 (`application/octet-stream`). При переходах внутри приложения **не запрашиваются**: данные берут `clientLoader`'ы напрямую из API |
| Гидратация | `window.__reactRouterContext` есть, язык и title меняются при переключении DE→EN→RU без перезагрузки; в консоли только ошибки Usercentrics (домен Preview не в allow-list аккаунта) |
| Капча | на `/kontakt` iframe reCAPTCHA загружается |
| Карта | чанк `PropertyMap` и запрос к `restcountries.com` выполняются, контейнера Leaflet нет — **так же на production** (`immo-tonn.com`, оба активных объекта): запрос к `restcountries.com` не проходит. Прежняя проблема, не регрессия |
| Индексация Preview | заголовок `X-Robots-Tag: noindex` на всех ответах, включая 404 (ставит Vercel) |
| Sitemap/robots | `sitemap.xml` — 18 URL, 12 hreflang-ссылок; `robots.txt` со строкой `Sitemap:` |

Не проверено: разный User-Agent на Vercel (браузер не позволяет его менять; логики по
User-Agent в конфигурации нет), реальный новый объект.

### Как повторить проверку на Vercel

Откройте ссылку Preview из проверки Vercel в PR (вы авторизованы в Vercel; защиту отключать
не нужно). Статусы удобно смотреть в DevTools → Network или `fetch('/zzz')` в консоли.

## Найденные проблемы и решения

| Проблема | Решение |
|---|---|
| `leaflet` обращается к `window` при импорте | карта грузится лениво после монтирования |
| На Vercel задан `VITE_RECAPTCHA_SITE_KEY` → при prerender рендерился `ReCAPTCHA` (CJS) и сборка падала | `ReCAPTCHA` рендерится только после монтирования (воспроизводится локально с любым значением ключа) |
| peer-конфликт `@react-router/dev` ↔ `react-router` | раздел 2 |
| `@react-router/node` должен быть в `dependencies` | перенесён |
| при `ssr:false` export `loader` вырезается из клиентской сборки | `clientLoader` не ссылается на `loader` |
| prerender передаёт путь со слэшем | нормализация в переключателе языка |
| API на невалидный ID отвечает 500, а не 404 | не исправлено (backend) |

## Наблюдения, требующие решения

- Данные объекта запрашиваются дважды (loader и прежний хук `usePropertyData`): 6 запросов к API
  вместо 3 при переходе на карточку.
- Адреса со слэшем в конце (`/immobilien/`, `/wertermittlung/`) отдают 200 тем же содержимым;
  спасает canonical. Единый вид даёт `trailingSlash: false` в `vercel.json` (не включено).
- Admin-страницы (`/add-property`, `/edit-object/…`) в prerender не входят, отдаются через rewrite.

## Не сделано / открыто

- `meta` есть не на всех страницах (около 10 без title/description/canonical; у DE-версий
  title сейчас пустой, у production был общий) — нужны тексты на 3 языках.
- Внутренние ссылки (≈44) не несут языкового префикса: на `/en/…` меню ведёт на DE-страницы.
- Тексты EN/RU для Home — временные (из существующих переводов); EN/RU Home и объекты
  закрыты `noindex` до готовности.
- Объекты EN/RU: в API нет переводов — решение по индексации не принято.
- Deploy Hook и вызов из backend не реализованы; пересборка при изменении объектов — вручную.
- Старые `src/app/App.tsx`, `main.tsx`, `index.html`, `Seo.tsx` не используются, оставлены.
- Редизайн Home (ветка `feat/home-redesign-sapphire`) в прототип не включён.
