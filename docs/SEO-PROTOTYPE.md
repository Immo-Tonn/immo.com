# Прототип: prerender + языковые URL (React Router framework mode)

Ветка `feat/seo-prerender-prototype`, draft PR. Стек прежний (Vite + React Router 7), добавлены
prerender, языковые URL и автопересборка. Это не финальная версия: к публикации ещё нужны
шаги из раздела «Перед публикацией». Откат — [ROLLBACK.md](ROLLBACK.md), автопересборка —
[AUTO-REBUILD.md](AUTO-REBUILD.md).

## Что реализовано

- **Рендеринг.** `ssr:false` + `prerender()` (`FE/react-router.config.ts`): все страницы × 3 языка
  и все объекты из API. Нет ответа API при сборке — сборка падает, прежний деплой остаётся.
- **Языки.** `/` = DE (прежние URL без изменений), `/en/…`, `/ru/…`; `/de/…` и любые другие
  префиксы — 404. Язык задаёт URL (не `localStorage`); `<html lang>` выставляется и в HTML, и
  после гидратации.
- **Мета** (`FE/src/seo/*`, тексты в `locales/*.json → seo`): уникальные title, description,
  self-canonical, OG для всех публичных страниц. hreflang — только между готовыми языками.
- **Готовность языка** (`FE/src/seo/readiness.json`) — единый реестр для hreflang, `noindex` и
  sitemap. Оценена по всему видимому тексту (автоматическое сравнение DE/EN/RU, см. ниже).
- **Ссылки и переключатель.** Все внутренние `Link`/`NavLink`/`navigate`/`Navigate` идут через
  `shared/lib/localeRouter` и сохраняют язык; переключатель ведёт на ту же страницу.
- **Данные.** Loader'ы отдают данные в HTML; повторные запросы убраны (см. ниже).
- **404.** Полноценная страница (заголовок, пояснение, ссылки на каталог и главную), одинаковая
  при прямом открытии и при переходе внутри приложения.
- **Sitemap / `built-objects.json` / `404.html`** — `FE/scripts/postbuild.mjs` из того же
  списка, что prerender.
- **Trailing slash:** единый вид без слэша (`vercel.json: trailingSlash:false`).
- **Backend:** вызов Deploy Hook после сохранения объекта (только этот механизм).

## Готовность языковых версий (по всему видимому тексту)

| Страница | DE | EN/RU | Основание |
|---|---|---|---|
| Home, Wertermittlung, Finanzierung, Kontakt, Verkaufssupport, Recht & Rat, Rechner | готова | готова | весь видимый текст переведён (совпадают только адрес/email) |
| Immobilien (список), карточки объектов | готова | **noindex** | в API нет переводов: названия, описания, города — по-немецки |
| Objektstyling | готова | **noindex** | текст страницы только по-немецки |
| Impressum, Datenschutz, Widerruf | готова | **noindex** | юридические тексты только по-немецки |
| Danke, админ-маршруты | — | — | закрыты `noindex` на всех языках |

Неготовые EN/RU страницы доступны пользователям, но не в sitemap, без hreflang и с `noindex`;
объекты индексируются только на DE. Ограничение: `alt`-тексты части картинок остаются
немецкими (не видны на странице) — на оценку готовности не влияли. Тексты title/description
для EN/RU написаны на основе содержимого страниц и требуют вычитки редактором.

## Результаты проверок

**Сборка:** `npm run build` (с заданным `VITE_RECAPTCHA_SITE_KEY`, как на Vercel), `tsc -b` —
0 ошибок; backend: `npm run test:rebuild` — 11 из 11. `npm run lint` в этом окружении не
запускается (нет `eslint-plugin-react`) — не проверено.

**Исходный HTML и sitemap (локально):** у каждой публичной страницы есть title, description,
canonical, OG, `<html lang>`, контент без JS; дублей title нет, кроме `noindex`-версий неготовых
языков. Sitemap — 30 URL (12 DE-страниц, 4 объекта, 14 EN/RU готовых страниц), 84 hreflang-связи
только у готовых страниц; `/en|ru/immobilien`, `/en/objectstyling`, юридические EN/RU — нет.

**Браузер, локально:** все внутренние ссылки на EN/RU-страницах локализованы (181 ссылка, не
локализованы только ссылки самого переключателя); клики по меню/подвалу/CTA/карточке сохраняют
язык; переключение DE→EN→RU→DE остаётся на той же странице.

**404 (хостинг с `404.html`):** `/zzz`, `/en/zzz`, `/de/immobilien`, несуществующий объект и
объект вне сборки — HTTP 404 и одинаковая страница; при переходе внутри приложения — тот же
результат. Объект вне сборки не показывается ни при прямом открытии, ни из приложения; в списке
его нет. Удалённый объект (API 404) → страница 404; сбой API (сеть, 5xx) → отдельная страница
«не удалось загрузить» (не 404); при сбое обновления данных уже отрисованный объект остаётся.

**Запросы к API:** переход на карточку — 3 (было 6), открытие prerender-карточки — 3 (тихое
обновление), список — 2.

## Известные ограничения и не проверено

- **Автопересборка проверена только на mock-сервере.** Реальный хук не создавался; весь путь
  (хук → сборка Vercel → новый объект на сайте) не проверен — см. [AUTO-REBUILD.md](AUTO-REBUILD.md).
  Новый объект появляется после успешной пересборки (минуты); до этого его URL отдаёт 404.
- Карта на карточке: контейнер Leaflet не появляется — запрос к `restcountries.com`
  не проходит; так же на production. Не исправлялось (отдельная задача).
- Нет H1 на `/finanzierung`, `/kontakt`, `/verkaufssupport`, `/rechner` (так же было до
  прототипа) — не менялось, чтобы не трогать внешний вид.
- В консоли Preview, кроме известных ошибок (карта, Usercentrics на домене Preview), ошибок не
  обнаружено; инструмент чтения консоли сбрасывает записи при переходах, поэтому проверка
  частичная.
- DOM-атрибут `href` переключателя языка в prerender-HTML не содержит `?query` (после
  гидратации клик сохраняет параметры).
- Старые `src/app/App.tsx`, `main.tsx`, `index.html`, `Seo.tsx` не используются, оставлены.
- Редизайн Home (ветка `feat/home-redesign-sapphire`) не переносился.

## Перед публикацией (что нужно сделать)

1. Принять решение по индексации EN/RU объектов и неготовых страниц (сейчас `noindex`).
2. Вычитать EN/RU мета-тексты (написаны мной по содержимому страниц).
3. Создать Deploy Hook на ветку прототипа, подключить `FRONTEND_DEPLOY_HOOK_URL` на сервере,
   пройти проверку целиком из AUTO-REBUILD.md (на тестовом объекте), затем — хук на `dev`.
4. Решить по страховочной пересборке по расписанию (потерянный запуск при перезапуске backend).
5. Проверить в Vercel настройки проекта (Production Branch, переменные окружения
   `VITE_*`, `VITE_RECAPTCHA_SITE_KEY` для Production).
6. Обновить `robots.txt`/Search Console: отправить новый sitemap после публикации.
7. Редирект/каноникализация старого `immo-tonn.de` (отдельная задача на сервере).
8. После слияния в `dev` (= публикация на production): проверить Production тем же набором
   проверок; откат — по ROLLBACK.md.
9. Затем — перенос редизайна Home.
