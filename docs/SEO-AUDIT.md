## 4. Объекты недвижимости и автопересборка

Реализовано и проверено в изолированной среде: новый объект появляется после успешной пересборки (до этого его URL → 404);
изменённый — после сборки (до неё прежний HTML, затем данные обновляются из API); удалённый — после сборки URL → 404,
из sitemap и списка исчезает; недоступный API при сборке — сборка падает, прежний деплой остаётся; сбой сборки Vercel —
сверка повторяет запуск. **С настоящим Vercel и боевым backend не проверено** (нет хука, нет публичного тестового backend):
точный план — [VERCEL-E2E-PLAN.md](VERCEL-E2E-PLAN.md).

**Проданные объекты — предложение.** Не удалять и не закрывать: URL остаётся 200 и индексируемым, на странице
виден статус «Verkauft», оферта (цена) в разметке не выводится. Это сохраняет страницу как подтверждение опыта
и не создаёт 404 для ссылок. Если объект долго продан и неинтересен, решение о `noindex` — за владельцем;
в коде это одна строка по `status === 'sold'` и сроку.

Ограничение: данные объектов в API только на немецком, поэтому `/en|ru/immobilien…` остаются `noindex`.
Фото объектов лежат на CDN в оригинальном размере (до 4,6 МБ) — в коде не исправляется, см. раздел 6.

## 6. Что не удалось проверить или требует вашего решения

1. Сквозная проверка с настоящим Vercel и боевым backend (нужен тестовый хук, публичный тестовый API).
2. Реальные Core Web Vitals (поле): GSC не отдаёт их через доступный интерфейс; смотреть отчёт «Основные интернет-показатели».
3. `www.immo-tonn.com`: добавить домен в проекте Vercel с редиректом на `immo-tonn.com` (сейчас сертификат не совпадает).
4. `immo-tonn.de`: отдаёт копию сайта. Рекомендация — постоянный 301-редирект на `immo-tonn.com` (управляется вне репозитория, ничего не менялось). Важно: backend (API) живёт на этом же домене, редирект должен касаться только страниц, а не `/api`.
5. Телефон: в Footer подпись «Tel.: 0251 625 60 763», но ссылка ведёт на мобильный 0174 345 44 19; в JSON-LD и Kontakt — только мобильный. Какой номер основной — уточнить.
6. Календарный `lastmod` в sitemap не выводится (в API нет даты изменения) — оставлено без выдумки.
7. Фото на CDN (Bunny): включить оптимизацию/ресайз на стороне CDN — самый крупный остающийся резерв скорости каталога.
8. Доступность калькулятора: у полей и `select` нет связанных подписей (Lighthouse). Изменение затрагивает форму калькулятора и вынесено из этой задачи.
9. Визуальные заголовки/тексты не менялись. Скрытых SEO-текстов нет. `llms.txt` существовал до задачи (коммит «Сделан immo-tonn.com каноническим доменом»), не расширялся и не считается условием попадания в ИИ-поиск.
