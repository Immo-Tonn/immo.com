# Проверка «поведение не изменилось» при визуальном редизайне

Цель: при редизайне остальных страниц меняется только оформление. `qa/baseline.json` — снимок
поведения **до** редизайна (ветка `feat/home-redesign-sapphire`, коммит `bf7e1c0`, боевой API читается
только GET-запросами; заявки перехватываются в браузере и никуда не уходят).

## Что фиксируется (кроме админки)
- видимый текст, ссылки, поля и кнопки всех публичных страниц на DE/EN/RU (+ страница 404);
- калькулятор: 21 набор входных данных × 4 варианта (`/finanzierung` DE, `/rechner` DE/EN/RU): значения
  полей, сообщения об ошибках, текст результата; текстовое содержимое PDF;
- форма контакта: сообщения валидации (3 языка), отправка успех/ошибка 500/ошибка 400 (перехват запроса);
- список объектов (порядок = порядок API, переход по карточке), страницы объектов: кнопки, фото, галерея,
  переход в калькулятор; переключение языка и его сохранение после обновления; переходы меню.

к нему перехватываются.)

## Известные особенности самого приложения (не связаны с редизайном)
1. **Платёж в калькуляторе нестабилен.** При одних и тех же видимых значениях «Monatliche Rate» меняется
   от запуска к запуску (≈ 0,2 %, например 1 814–1 817 € для 500 000 € / 100 000 € / 3,5 %), при любой скорости
   ввода; а использованный срок (≈ 35 лет) не совпадает с показанным в поле «Laufzeit» (31). Причина — связка
   «срок ↔ погашение» через эффекты в `MortgageCalculator.tsx`. Поэтому платёж сравнивается отдельно,
   с допуском 1 %, остальной результат — точно. Логика не менялась и менять её редизайн не будет.
2. Сценарии отправки формы зависят от тестовой reCAPTCHA Google (иногда не проходит) — в таком случае
   сценарий пропускается и помечается `~`.
3. Данные объектов — боевые; если объект изменили между снимками, список/карточки отличатся.
